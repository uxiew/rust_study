# 31.2 scoped-threadpool

普通的 `thread::spawn` 要求闭包是 `Send + 'static`，因为新线程可能比调用它的函数活得更久。若线程一定先在函数返回前结束，是否可以直接借用局部对象，不必把数据交给带引用计数的 `Arc`？这正是**作用域线程**解决的问题。

::: tip 新版变化
自 Rust 1.63 起，`std::thread::scope` 可以让线程借用局部数据，不再需要为这一功能引入第三方依赖。但 `scope.spawn` 创建的是新线程，不是向固定大小的线程池提交任务。
:::

```rust
use std::thread;

fn main() {
    let mut values = [1, 2, 3, 4];

    thread::scope(|scope| {
        let (left, right) = values.split_at_mut(2);
        scope.spawn(move || left[0] += 10);
        scope.spawn(move || right[0] += 10);
    });

    assert_eq!(values, [11, 2, 13, 4]);
}
```

两个可变切片不重叠，返回前子线程都已结束，因此无需 `Arc` 或锁。如果已有代码使用 [`scoped_threadpool`](https://docs.rs/scoped_threadpool/latest/scoped_threadpool/)，其区别是多个作用域任务可以复用池中的工作线程：

在 Edition 2024 的 Cargo 项目中安装依赖，再把下面的代码放到 `src/main.rs`，用 `cargo run` 运行。示例依赖外部 crate，单文件 `rustc` 审计跳过此围栏。

```sh
cargo add scoped_threadpool@0.1.9
```

```rust,ignore,no_run
use scoped_threadpool::Pool;

fn main() {
    let mut pool = Pool::new(2);
    let mut values = [1, 2, 3, 4];

    pool.scoped(|scope| {
        for n in &mut values {
            scope.execute(move || *n += 1);
        }
    });

    assert_eq!(values, [2, 3, 4, 5]);
}
```

池的 `scoped` 方法声明如下（省略实现）：

```text
pub fn scoped<'pool, 'scope, F, R>(&'pool mut self, f: F) -> R
where
    F: FnOnce(&Scope<'pool, 'scope>) -> R,
```

这里没有要求 `F: 'static`。池通过 `Scope` 管理任务的生命周期，在 `scoped` 返回前等它们全部结束，因此每个任务可以借用 `values` 的一个元素。
