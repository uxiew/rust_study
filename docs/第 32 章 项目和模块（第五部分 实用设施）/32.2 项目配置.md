# 32.2 项目配置

`Cargo.toml` 描述一个 Cargo 包。`package.edition` 指定该包源代码用哪一版语言规则；依赖可以使用不同的 Edition，不必一起迁移。

```toml
[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]
serde = { version = "1", features = ["derive"] }

[build-dependencies]
cc = "1"

[dev-dependencies]
tempfile = "3"
```

| 配置 | 谁可以使用 |
| --- | --- |
| `[dependencies]` | 包的库和二进制等普通目标 |
| `[build-dependencies]` | 构建脚本 `build.rs` |
| `[dev-dependencies]` | 测试、示例和基准测试 |

可以用 `cargo add serde --features derive` 添加依赖；加 `--dev` 或 `--build` 可写入对应的表。用 `cargo remove` 删除依赖。Rust 2018 起，通常不必再写 `extern crate`；在源代码里直接用 `serde::…` 或 `use serde::…`。

## crate 版本号

Cargo 依赖采用[语义化版本](https://semver.org/lang/zh-CN/)。稳定 API 的不兼容改动通常升级主版本，向后兼容的新功能升级次版本，兼容性修复升级补丁版本。Cargo 默认的插入符要求（`^`）允许更新到最左侧非零数字不变的兼容版本。

| 版本要求 | 可选版本 |
| --- | --- |
| `"1.2.3"` 或 `"^1.2.3"` | `>=1.2.3, <2.0.0` |
| `"0.2.15"` | `>=0.2.15, <0.3.0` |
| `"~1.2.3"` | `>=1.2.3, <1.3.0` |
| `"1.*"` | `>=1.0.0, <2.0.0` |
| `"=1.2.3"` | 仅 `1.2.3` |

依赖可以来自 crates.io、Git 或本地路径：

```toml
[dependencies]
serde = "1"                                              # crates.io
rand = { git = "https://github.com/rust-random/rand" }    # Git
my_local = { path = "../my_local" }                       # 本地包
```

Git 依赖默认使用仓库默认分支；可用 `branch`、`tag` 或 `rev` 指定分支、标签或提交。本地相对路径以写下该依赖的 `Cargo.toml` 所在目录为起点。

`Cargo.toml` 记的是版本约束；`Cargo.lock` 记的是本次解析选中的具体版本和来源。通常把 `Cargo.lock` 纳入版本管理以重现本仓库的构建和测试；即使库项目提交了锁文件，下游项目仍使用它自己的锁文件解析依赖。`cargo build --locked` 要求在不改动锁文件的前提下完成构建。

## Profiles 配置文件

`cargo build` 默认使用 `dev` 构建配置；`cargo build --release` 使用 `release`。可在 `Cargo.toml`（工作空间则在根清单）里给不同场景设置优化级别：

```toml
[profile.dev]
opt-level = 0

[profile.release]
opt-level = 3
```

上面是两个配置的默认优化级别。`dev` 侧重构建速度，`release` 侧重运行性能。更多选项见 [Cargo 构建配置](https://doc.rust-lang.org/cargo/reference/profiles.html)。

## 32.2.1 cargo 配置文件

清单描述项目；`.cargo/config.toml` 配置 Cargo 工具本身，例如构建参数、命令别名和输出。Cargo 会从当前目录向上寻找配置，也会读取 `$CARGO_HOME/config.toml`（`CARGO_HOME` 默认是 `$HOME/.cargo`）。启动 Cargo 的目录会影响找到哪些配置。

```toml
[build]
jobs = 4

[term]
color = "auto"

[alias]
rr = "run --release"
```

新配置用 `config.toml`；同一目录下若同时存在旧名 `config` 和 `config.toml`，Cargo 优先使用不带扩展名的文件。详见 [Cargo 配置](https://doc.rust-lang.org/cargo/reference/config.html)。

## 32.2.2 workspace

一个工作空间可以管理多个包。成员各有自己的 `Cargo.toml`，但默认共用根目录的 `Cargo.lock` 和 `target/`。共用锁文件不代表同一个外部库只能解析出一个版本；不兼容的依赖要求仍可能引入多个版本。

下面是一个虚拟工作空间：根清单没有 `[package]`，不能从包的 Edition 推断解析器版本。要使用 Edition 2024 对应的解析规则，显式写 `resolver = "3"`。

```toml
[workspace]
members = ["project1", "lib1"]
resolver = "3"
```

```text
workspace/
├── Cargo.toml
├── project1/
│   ├── Cargo.toml
│   └── src/main.rs
└── lib1/
    ├── Cargo.toml
    └── src/lib.rs
```

如果 `project1` 要使用 `lib1`，在 `project1/Cargo.toml` 中声明依赖，再从工作空间根目录运行 `cargo run -p project1`。

```toml
[dependencies]
lib1 = { path = "../lib1" }
```

## 32.2.3 build.rs

如果包根目录有 `build.rs`，Cargo 会在编译该包前先编译并按需运行构建脚本。常见用途包括编译原生库、配置链接参数、生成 Rust 源码。脚本有独立的 `[build-dependencies]`。

| 常见环境变量 | 含义 |
| --- | --- |
| `CARGO_MANIFEST_DIR` | 包清单所在目录（不是 `Cargo.toml` 文件本身） |
| `HOST` / `TARGET` | 脚本运行的平台 / 包要构建的目标平台 |
| `OUT_DIR` | 构建脚本写入生成文件的目录 |

### 构建时注入环境变量

例如，在 Git 仓库的 `build.rs` 中获取当前提交。没有 Git 或没有可用提交时，不设置变量：

```rust,no_run
use std::process::Command;

fn main() {
    if let Ok(output) = Command::new("git").args(["rev-parse", "HEAD"]).output() {
        if output.status.success() {
            let commit = String::from_utf8_lossy(&output.stdout);
            println!("cargo::rustc-env=GIT_COMMIT={}", commit.trim());
        }
    }
}
```

Cargo 识别 `cargo::rustc-env=键=值`，在编译包时设置该环境变量。这种指令写法需要 Cargo 1.77 或更新版本。`src/main.rs` 用 `option_env!` 在编译时读取；未设置时保留默认值：

```rust
fn main() {
    println!("提交：{}", option_env!("GIT_COMMIT").unwrap_or("未知"));
}
```

这里演示的是构建时注入，不是 Git 状态跟踪。Cargo 不一定会在每次 Git 提交后重跑脚本；要手动刷新示例，可以先执行 `cargo clean` 再构建。实际项目可按需用 [`cargo::rerun-if-changed`](https://doc.rust-lang.org/cargo/reference/build-scripts.html#rerun-if-changed) 跟踪相关输入。

### 构建时生成 rs 文件

也可以把构建结果写成 Rust 源码。下面是另一个独立示例：`build.rs` 从 Cargo 的环境变量读取包版本，把常量写到 `OUT_DIR`，不修改源码目录。

```rust,no_run
use std::{env, fs, io, path::PathBuf};

fn main() -> io::Result<()> {
    let out_dir = PathBuf::from(env::var_os("OUT_DIR").expect("需要由 Cargo 运行"));
    let version = env::var("CARGO_PKG_VERSION").expect("Cargo 未提供包版本");
    fs::write(
        out_dir.join("build_info.rs"),
        format!("pub const VERSION: &str = {version:?};\n"),
    )
}
```

把以下代码保存为同一个包的 `src/main.rs`，运行 `cargo run`。这段代码依赖上面的构建脚本生成文件，不能单独交给 `rustc`。

```rust,ignore,no_run
include!(concat!(env!("OUT_DIR"), "/build_info.rs"));

fn main() {
    println!("包版本：{VERSION}");
}
```

`include!` 在编译时把生成的 Rust 代码包含到当前位置；`concat!` 把 `OUT_DIR` 和文件名拼成路径。更多细节见 [Cargo 构建脚本](https://doc.rust-lang.org/cargo/reference/build-scripts.html)。
