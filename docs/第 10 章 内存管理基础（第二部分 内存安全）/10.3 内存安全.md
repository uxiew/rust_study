# 10.3 内存安全

Rust 保证健全的安全代码不会发生悬空引用、越界读写、重复释放或数据竞争等未定义行为。它不承诺程序永远成功，也不承诺没有逻辑错误。

| 情况 | Rust 怎么处理 |
| --- | --- |
| 返回已释放数据的引用 | 借用检查在编译时拒绝。 |
| 安全地用索引访问切片 | 运行时检查边界；也可以用 `get` 取得 `Option`。 |
| 引用计数环 | 可能泄漏，但泄漏本身不是未定义行为。 |
| 内存耗尽 | 标准库默认的分配失败处理通常中止进程；`Vec::try_reserve` 等接口可返回某些分配失败。 |
| 错误使用裸指针 | 可能是未定义行为，不能把是否触发段错误当作判断依据。 |

数据竞争指没有适当同步的冲突内存访问，其中至少一次是写入。它不同于结果依执行顺序变化的逻辑竞态；Rust 仍可能有逻辑竞态或死锁。

`panic` 是程序触发的错误处理机制，可以展开栈或中止。段错误通常是操作系统对非法内存访问发出的信号；core dump 是某些退出场景的诊断产物，不是某种 Rust 异常类型。
