# 17.3 析构函数泄漏

不能假设每个值最终都会运行 `Drop`。强引用环、进程中止和安全函数 [`std::mem::forget`](https://doc.rust-lang.org/std/mem/fn.forget.html) 都可能跳过析构。因此，`unsafe` 封装不能把「守卫的析构一定会执行」当作内存安全前提。

| 情况 | 可以依赖什么 |
| --- | --- |
| `drop(value)` | 消费值，通常立即析构。 |
| `forget(value)` | 消费值，不运行析构；资源可能泄漏。 |
| `static` 与 `const` | `static` 项退出时不析构；`const` 是表达式中的值，不是独立的全局变量。 |

::: tip 新版变化
早期实验 API `thread::scoped` 依赖可忘记的守卫等待线程，因此从标准库移除。自 Rust 1.63 起，稳定的 [`std::thread::scope`](https://doc.rust-lang.org/std/thread/fn.scope.html) 由作用域本身等待未手动加入的线程，和调用方是否保留某个句柄无关。
:::

```rust
fn main() {
    use std::thread;

    let mut numbers = vec![1, 2];
    thread::scope(|scope| {
        scope.spawn(|| numbers.push(3));
    });
    assert_eq!(numbers, [1, 2, 3]);
}
```

同一个原则也适用于 `Vec::drain`：若忘记迭代器，容器可能丢失或泄漏元素，但安全代码仍不能访问未初始化内存。
