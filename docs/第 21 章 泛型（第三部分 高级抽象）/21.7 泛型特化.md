# 21.7 泛型特化

泛型特化允许为一组类型提供通用实现，再为其中较具体的类型覆盖部分实现。这里讨论的是编译期选择，并非运行时动态分派。

::: tip 新版变化
Rust 1.100 稳定版不支持特化。以下示例需 Nightly 的 `specialization`；它尚未完成，不宜作为稳定 API 的基础。Nightly 另有约束更严格的 `min_specialization`。
:::

## 21.7.1 特化的意义

最具体且合法的实现优先。这里 `bool` 覆盖通用实现，其他类型仍走通用路径。

```rust:{channel:"nightly",edition:"2024"}
#![feature(specialization)]

trait Describe {
    fn describe(&self) -> &'static str;
}

impl<T> Describe for T {
    default fn describe(&self) -> &'static str { "通用" }
}

impl Describe for bool {
    fn describe(&self) -> &'static str { "布尔值" }
}

fn main() {
    assert_eq!(42.describe(), "通用");
    assert_eq!(true.describe(), "布尔值");
}
```

## 21.7.2 default 上下文关键字

`default fn` 表示更具体的 impl 可以替换该方法。不带 `default` 的方法不能这样替换。关联类型也可参与特化；若它可被替换，就不能在泛型调用点假定它总等于通用实现中写下的具体类型。

标准库内部可用编译器特性优化某些类型的 `ToString` 路径。稳定版用户直接用 `"Rust".to_string()` 即可，不需要开启特化，也不存在标准库内置的 `#[derive(Display)]`。

## 21.7.3 交叉 impl

| 两个实现的关系 | 选择 |
| --- | --- |
| 互不重叠 | 选择唯一匹配的实现 |
| 具体实现包含于通用实现 | Nightly 特化允许在符合规则时选择更具体的实现 |
| 仅部分相交，例如 `T: A` 和 `T: B` | 无法确定哪个更具体；增加 `T: A + B` 也不能令这两个 impl 合法 |

稳定版上，下面两个 impl 因重叠而报 E0119：`bool` 同时匹配二者。

```rust,compile_fail,no_run
trait Describe {}
impl<T> Describe for T {}
impl Describe for bool {}
```

在稳定版需要不同行为时，可以为不同实现使用不同包装类型，例如 `Plain<T>` 和 `Verbose<T>`，由调用者显式选择。

参见 [特化跟踪议题](https://github.com/rust-lang/rust/issues/31844)。
