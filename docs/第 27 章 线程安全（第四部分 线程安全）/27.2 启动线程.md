# 27.2 启动线程

Rust 标准库中与线程相关的内容在 `std::thread` 模块中。这里的线程是原生操作系统线程，不是异步任务。

创建线程的方法为：

```rust
use std::thread;

fn main() {
    thread::spawn(|| {
        // 这里是新建线程的执行逻辑。
    });
}
```

丢弃 `spawn` 返回的句柄会分离线程，而不是停止它。分离的线程可以在创建它的线程结束后继续执行，但进程退出时不会等待它。

如果我们需要等待子线程执行结束，那么可以使用 `join` 方法：

```rust
use std::thread;

fn main() {
    // child 的类型是 JoinHandle<T>，这个 T 是闭包的返回类型。
    let child = thread::spawn(|| 6 * 7);
    // 父线程等待子线程结束，并拿到返回值。
    let res = child.join().expect("子线程 panic");
    assert_eq!(res, 42);
}
```

如果我们需要为子线程指定更多的参数信息，那么在创建的时候可以使用 Builder 模式：

```rust
use std::thread;

fn main() {
    let worker = thread::Builder::new()
        .name("worker".into())
        .spawn(|| 6 * 7)
        .expect("无法创建子线程");

    assert_eq!(worker.join().expect("子线程 panic"), 42);
}
```

如果不需要设置线程名或栈大小，直接用 `thread::spawn(|| 6 * 7)` 即可。区别是 `Builder::spawn` 会将创建失败作为 `io::Result` 返回，而 `thread::spawn` 会 panic。

| API | 用途 |
| --- | --- |
| `sleep(duration)` | 阻塞当前线程至少指定的时长 |
| `yield_now()` | 暂时让出执行机会，不保证切换到其他线程 |
| `current()` | 获取当前线程的句柄 |
| `park()` / `unpark()` | `unpark` 提供一个通知令牌；`park` 消耗令牌或等待，也可能虚假唤醒 |

`sleep` 不能代替线程同步；用 `park` 等待业务条件时，应在循环里重新检查条件。


下面把 `Builder`、`park` 和 `unpark` 放在一起。父线程先更新原子标记，再发通知；子线程醒来仍需检查标记。这也覆盖了通知先于 `park` 的情况。

```rust
use std::{sync::atomic::{AtomicBool, Ordering}, thread};

fn main() {
    let ready = AtomicBool::new(false);
    thread::scope(|scope| {
        let child = thread::Builder::new()
            .name("child1".to_string())
            .spawn_scoped(scope, || {
                println!("进入子线程");
                while !ready.load(Ordering::Acquire) {
                    thread::park();
                }
                println!("子线程继续");
            })
            .unwrap();

        ready.store(true, Ordering::Release);
        child.thread().unpark();
        child.join().unwrap();
    });
    println!("子线程已结束");
}
```
