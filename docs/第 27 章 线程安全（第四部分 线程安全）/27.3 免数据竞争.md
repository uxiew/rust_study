# 27.3 免数据竞争

先试着在子线程中借用一个局部变量：

```rust,compile_fail,no_run
use std::thread;

fn main() {
    let mut health = 12;
    thread::spawn(|| health *= 2);
}
```

预期报错 **E0373**：`spawn` 要求闭包满足 `'static`，因为线程可能活得比调用者更久；这里闭包捕获了对局部变量的短期可变借用。

| 捕获方式 | 线程拿到什么 |
| --- | --- |
| 借用局部变量再用 `spawn` | 局部引用可能失效，编译器拒绝 |
| 用 `move` 捕获 `Copy` 值（如整数） | 值的副本，不会改变原变量 |
| 用 `move` 捕获非 `Copy` 值（如 `Vec`） | 值的所有权，调用者不能再使用原变量 |

下面给 `Vec` 加上 `move`，却仍在原线程读取它：

```rust,compile_fail,no_run
use std::thread;

fn main() {
    let mut values = vec![1];
    thread::spawn(move || values.push(2)).join().unwrap();
    println!("{values:?}");
}
```

预期报错 **E0382**：`values` 已移入闭包，`join` 不会把所有权还给调用者。

::: tip 新版变化
从 Rust 1.63 起，稳定版的 `thread::scope` 可以借用外部的局部变量。作用域返回前会等待所有未手动 `join` 的作用域线程，因此下面不需要 `move`，也不需要 `Arc`。
:::

```rust
use std::thread;

fn main() {
    let mut health = 12;
    thread::scope(|scope| {
        scope.spawn(|| health *= 2);
    });
    assert_eq!(health, 24);
}
```

**数据竞争**指不同线程以无法保证先后顺序的方式访问同一内存位置，其中至少一个是写入，且并非所有访问都是原子的。安全 Rust 在其依赖的 `unsafe` 实现遵守安全契约的前提下防止数据竞争，但不会阻止死锁或结果依赖调度的逻辑错误。需要共享可变状态时，可用锁或原子操作；需要在线程之间转移数据时，也可以发送消息。
