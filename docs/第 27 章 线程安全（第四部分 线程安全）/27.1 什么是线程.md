# 27.1 什么是线程

线程是操作系统调度执行的基本单位。同一进程内的线程共享地址空间；有多个 CPU 核心时，它们还可以并行执行。但共享数据也需要同步。

多线程编程在许多领域是不可或缺的。但是，多线程并行，非常容易引发数据竞争，而且还非常不容易被发现和 debug。下面，我们用 C++语言来演示一下什么是数据竞争（这里是故意写的有 bug 的版本）：

```c++
#include <iostream>
#include <stdlib.h>
#include <thread>
#include <string>

#define COUNT 1000000
int g_num = 0;

void thread1()
{
    for (int i=0; i<COUNT; i++){
        g_num++;
    }
}

void thread2()
{
    for (int i=0; i<COUNT; i++){
        g_num--;
    }
}

int main(int argc, char* argv[])
{
    std::thread t1(thread1);
    std::thread t2(thread2);
    t1.join();
    t2.join();

    std::cout << "final value:" << g_num << std::endl;
    return 0;
}
```

我们可以使用`g++ -pthread -std=c++11 temp.cpp`命令编译这段代码。

两个线程分别对 `g_num` 加 1 和减 1，次数相同。如果同步正确，结果应当是 0。但这里有数据竞争，按 C++ 规则属于**未定义行为**，不能假定结果总是 0 或一定不是 0；`volatile` 也不能提供线程同步。

用一个简化模型可以理解为什么会丢失更新：为普通变量加`1`减`1` 这样的操作并非“原子”操作。我们简化一下这个过程，可以将它分为三个步骤：读数据、执行计算、写数据。理想情况下，我们期望的执行流程应该是下面这样的：

| Thread 1 | Thread 2 | 读/写 | 变量值 |
| --- | --- | --- | --- |
|       |       |     | 0 |
| 读数据 |       | ←  | 0 |
| 加 1  |       |     | 0 |
| 写数据 |       | →  | 1 |
|       | 读数据 | ←  | 1 |
|       | 减 1  |     | 1 |
|       | 写数据 | →  | 0 |

如果两个线程都在写回之前读到同一个初值，后写回的一方就可能覆盖前一方的结果：

| Thread 1 | Thread 2 | 读/写 | 变量值 |
| --- | --- | --- | --- |
|       |       |     | 0 |
| 读数据 |       | ←  | 0 |
|       | 读数据 | ←  | 0 |
| 加 1  |       |     | 0 |
|       |  减 1 |     | 0 |
| 写数据 |       | →  | 1 |
|       | 写数据 | →  | -1 |

上表只解释丢失更新，不是 C++ 对实际执行的保证。下一节转向 Rust；安全 Rust 不允许用这种方式无同步地共享可变数据。
