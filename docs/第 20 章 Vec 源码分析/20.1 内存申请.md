# 20.1 内存申请

`Vec<T>` 区分已初始化的元素数 `len` 和不扩容可容纳的元素数 `capacity`。Rust 1.100.0 的 [`Vec` 源码](https://doc.rust-lang.org/1.100.0/src/alloc/vec/mod.rs.html) 把两项职责分开：`Vec` 保存 `len`，内部 [`RawVec<T, A>`](https://doc.rust-lang.org/1.100.0/src/alloc/raw_vec/mod.rs.html) 管理分配、容量和分配器。

| 创建方式 | 长度 | 容量 |
| --- | --- | --- |
| `Vec::<u32>::new()` | 0 | 0，不预分配。 |
| `Vec::<u32>::with_capacity(n)` | 0 | 至少为 `n`；预留空间没有初始化元素。 |
| `Vec::<()>::new()` | 0 | `usize::MAX`；零大小类型不为元素分配字节。 |

::: tip 新版变化
Rust 1.100.0 稳定了 `Vec<T, A>` 的分配器参数及 `Vec::new_in`、`Vec::with_capacity_in` 等接口。一般用默认的 `Global`；下面用 `System` 演示按容器选择分配器。这不表示所有扩展接口都已稳定，例如 `Vec::try_with_capacity_in` 仍不属于稳定 API。
:::

```rust
fn main() {
    use std::alloc::System;

    let mut values: Vec<u32, System> = Vec::with_capacity_in(4, System);
    assert_eq!(values.len(), 0);
    assert!(values.capacity() >= 4);
    values.push(42);
    assert_eq!(values.as_slice(), &[42]);
    assert_eq!(Vec::<()>::new().capacity(), usize::MAX);
}
```
