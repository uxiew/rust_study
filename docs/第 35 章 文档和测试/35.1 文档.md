# 35.1 文档

`cargo doc` 调用 rustdoc 生成 HTML，默认写入 `target/doc/`；用 `cargo doc --open` 可以构建后打开文档。普通的 `//` 和 `/* … */` 不会进入生成的文档。

| 文档注释 | 说明对象 |
| --- | --- |
| `///` 或 `/** … */` | 后面的项，例如函数或结构体 |
| `//!` 或 `/*! … */` | 所在的 crate 或模块 |

文档支持 Markdown。常见标题有 `# Examples`（用法）、`# Errors`（错误条件）、`# Panics`（何时 panic）和 `# Safety`（调用不安全接口必须满足的条件）。用 [intra-doc 链接](https://doc.rust-lang.org/rustdoc/write-documentation/linking-to-items-by-name.html)可以直接指向代码中的项，例如写 ``[`Buffer`]``，不用维护生成的 HTML 地址。

下面是一个可以保存到库项目 `src/lib.rs` 的示例。库文档链接到 `Buffer`，而 `Examples` 中的 Rust 代码可作为文档测试运行：

```rust
//! 管理字节缓冲区，参见 [`Buffer`]。

/// 一个字节缓冲区。
///
/// # Examples
///
/// ```
/// let bytes = Vec::<u8>::with_capacity(10);
/// assert!(bytes.is_empty());
/// ```
pub struct Buffer;
```

模块内也可以使用内层注释；下面的 `//` 留给读源码的人，不会出现在生成的页面里：

```rust
pub mod format {
    //! 字节缓冲区的格式化工具。

    /// 以十六进制格式显示一个字节。
    pub fn as_hex(byte: u8) -> String {
        // 保留前导零。
        format!("{byte:02x}")
    }
}
```

`cargo test` 会运行符合条件的库文档测试；只想运行文档测试时，用 `cargo test --doc`。代码围栏还可以注明验证方式：

| 围栏标记 | rustdoc 的行为 |
| --- | --- |
| 无标记或 `rust` | 编译并运行，代码应成功完成 |
| `should_panic` | 编译并运行，代码应发生 panic |
| `no_run` | 只编译，不运行 |
| `compile_fail` | 预期无法编译；旁边应说明为什么不成立 |
| `ignore` | 跳过该示例；仅在无法自动验证时使用 |

::: tip 新版变化
旧的 `external_doc` 特性已移除。自 Rust 1.54 起，可以在稳定版用 `#[doc = include_str!("…")]` 引入外部 Markdown。
:::

下面的声明需要与 `src/lib.rs` 同目录的 `src/overview.md`，其中直接写 Markdown，不必加 `///`：

```rust,ignore,no_run
#[doc = include_str!("overview.md")]
pub struct MyAwesomeType;
```

## docs.rs

[docs.rs](https://docs.rs/) 使用 Nightly 工具链为发布到 crates.io 的包自动构建和托管文档。这不意味着包本身必须依赖 Nightly。目标平台、启用的特性等选项可在 `Cargo.toml` 的 `[package.metadata.docs.rs]` 中[配置](https://docs.rs/about/metadata)。
