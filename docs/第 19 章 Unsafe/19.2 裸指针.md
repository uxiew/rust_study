# 19.2 裸指针

Rust 提供 `*const T` 和 `*mut T`。指针可以转换类型，但转换本身不会改变有效访问的范围，也不会凭空增加读写权限。

裸指针相对于其他的指针，如 `Box`，`&`，`&mut` 来说，有以下区别：

* 裸指针可以为空，而且编译器不保证裸指针一定指向一个合法的内存地址；

* 不会执行任何自动化清理工作，比如自动释放内存等；

* 裸指针可以复制。编译器不因复制而延长其访问权限；从引用派生的裸指针仍要遵守相应规则。

创建或转换裸指针本身通常是安全的；解引用、指针读写和部分指针运算需要证明额外的前提。

示例代码如下：

---

```rust
fn main() {
    let mut value = 1_u32;
    let ptr = &raw mut value;
    // SAFETY: ptr 指向仍存活、已对齐的 value；期间没有其他访问。
    unsafe { ptr.write(2) };
    assert_eq!(value, 2);
}
```

如果把指向 `u32` 的指针转换成 `*mut i64`，这个转换不会让原对象变成八字节，也不会保证它符合 `i64` 的对齐要求。不能通过它执行八字节写入。

可以把原书的例子拆成两步，分别问“能不能造出这样的地址表示”和“能不能拿它访问对象”：

| 操作 | 结论 |
| --- | --- |
| 把 `*mut u32` 转成 `*mut i64` | 转换可以发生，不访问缓冲区。 |
| 通过结果写入一个 `i64` | 需要八个可写字节和足够的对齐；原对象不能提供这种保证。 |
| 改用 `write_unaligned` | 只放宽对齐条件，不会增加可写的字节。 |

可以借用原书的比喻：“城门失火，殃及池鱼”。越界访问确实可能影响其他状态，但不能假定两个局部值在栈上相邻，也不能把某次打印结果当成行为保证。

## 从裸指针构造引用

另一种错误是把地址为零的指针直接转换为共享引用。产生无效引用本身就违反了契约，并不是等观察到段错误才出问题。

如果接口用空指针代表缺省值，可以提前拦截它。但非空仍不足以证明有效：调用者必须确保指针可读、对齐、已初始化，并保证返回引用的生命周期和别名约束。

---

```rust
/// # Safety
/// 非空指针在 'a 内必须能被共享读取一个已初始化的 i32。
unsafe fn raw_to_ref<'a>(p: *const i32) -> Option<&'a i32> {
    // SAFETY: 非空时，引用的前提由调用者保证。
    unsafe { p.as_ref() }
}

fn main() {
    let value = 10;
    // SAFETY: 指针来自有效共享借用，结果仅在 value 存活时使用。
    assert_eq!(unsafe { raw_to_ref(&raw const value) }, Some(&10));
    // SAFETY: 空指针按约定返回 None。
    assert_eq!(unsafe { raw_to_ref(std::ptr::null()) }, None);
}
```

---

普通引用还有自己的别名约束，例如使用 `&mut T` 时必须保证对数据的独占访问。这些约束条件，在 unsafe 场景下是很容易被打破的，而编译器并没有能力帮我们自动检查出来。我们之所以需要 unsafe，只是因为某些代码只有在特定条件下才是安全的，而这个条件我们没有办法利用类型系统表达出来，所以这时候需要依靠我们自己来保证。

大家千万不要到处滥用 unsafe。当你不得不使用 unsafe 的时候，请一定注意，这并不意味着你就可以乱写不安全的代码，相反，它的意思是“编译器请相信我，这段代码依然是安全的，它的安全性由我自己负责”。

## 计算新地址不代表读写合法

如果地址是由偏移得到的，要分别核对计算与访问的前提。`add` 和 `offset` 按元素做偏移，要求满足相应的同一分配范围约束；`wrapping_add` 可以在不满足该范围条件时计算指针，但其结果不可因此解引用。允许表示“末尾之后一个位置”也不代表那里有可读取的末尾元素。

裸指针也有很多有用的成员方法，读者可以参考标准文档中的“Primitive Type Pointer”。比如，裸指针并不直接支持算术运算，而是提供了一系列成员方法 offset wrapping\_offset 等来实现指针的偏移运算。
