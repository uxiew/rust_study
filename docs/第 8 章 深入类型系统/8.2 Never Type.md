# 8.2 Never Type

## 从值的个数推算所需的位数

如果一个类型有 `N > 0` 种可能的值，要把这些值分别编码，至少需要多少个 bit 呢？`b` 个 bit 可以表示 `2^b` 种位模式，所以需要满足 `2^b >= N`，即至少需要 `ceil(log2(N))` 个 bit。比如，`bool` 的基数是 2，只需 1 个 bit 就可以区分真假；这只是信息量的下界，并不是 Rust 的内存布局，Rust 的 `bool` 实际占 1 个字节。

像 unit 类型和没有字段的结构体，都可以类比为代数中的数字 1。因为只有一个值，`log2(1) == 0`，不存储任何位也能区分所有可能的值。这样的零大小类型有实际用处。例如，旧版标准库的 `HashSet` 曾采用下面的表示（历史源码节选，并非当前实现）：

```text
pub struct HashSet<T, S = RandomState> {
    map: HashMap<T, (), S>,
}
```

所谓 `HashSet`，就像只有键没有值的 `HashMap`：把键值对的“值”设为 `()`，就不必为值另外存储数据。当前标准库把实现委托给内部哈希集合；这不改变前面关于基数的推导。

没有变体的枚举可以类比为代数中的 0。例如：

```rust
enum Never {}
```

如果想写 `let e = Never::某个变体;`，却根本没有变体可以选；也就无法为结果分配任何有效的位模式。这里的 `log2(0)` 没有定义，并不意味着内存中存在负数位。

`()` 有一个值 `()`；空枚举没有变体，因此没有值。`!` 是 Rust 内置的无值类型，适合描述**不会正常返回**的表达式，例如 `return`、`continue` 或 `panic!`。无值不等于占用负数位，也不等于所有零大小类型都无值。

::: tip 新版变化
[从 Rust 1.100.0 起，`!` 稳定用于一般类型位置](https://doc.rust-lang.org/1.100.0/releases.html#version-11000-2026-11-12)，包括关联类型和泛型实参；更早的 Stable 已允许把它用作函数返回类型。
:::

早期 Rust 对发散函数做特殊处理，让有发散分支的表达式能通过类型检查；[RFC 1216](https://rust-lang.github.io/rfcs/1216-bang-type.html) 则把这一行为统一到 `!` 的类型规则中。空枚举也没有值，却不能像 `!` 那样直接强制转换成其他类型。

## 分支中不会产生的值

```rust
fn main() {
    let mut total = 0;
    for value in [2, -1, 4] {
        let x: i32 = if value >= 0 { value } else { continue };
        total += x;
    }
    assert_eq!(total, 6);
}
```

`continue` 分支会直接开始下一轮，不会给 `x` 赋值。因此该分支的 `!` 可以强制转换成另一个分支需要的 `i32`；这并不是在运行时把一个值转成整数。

## 泛型代码可以接受发散函数

例如，一个接收函数的泛型函数用 `T` 代表该函数的返回类型。传入 `std::process::exit` 时，`T` 就可以是 `!`：

```rust
fn call_fn<T>(f: impl Fn(i32) -> T, arg: i32) -> T {
    f(arg)
}

fn exit_through_generic(code: i32) -> ! {
    call_fn(std::process::exit, code)
}
```

这里只定义包装函数，不调用它：一旦调用，就会结束整个进程，而不是给调用者返回一个值。

## 类型可帮助判断代码是否可达

```rust,no_run
fn main() {
    let t = std::thread::spawn(|| -> ! { panic!("nope") });
    let _: ! = t.join().unwrap();
    println!("hello"); // 不可达
}
```

类型标注告诉我们闭包不可能正常返回，`join()` 的成功分支也不可能提供值。在这个例子里线程会 panic，`join()` 返回错误，随后 `unwrap()` 也会 panic。编译器不必执行线程，就能根据 `unwrap()` 产生的 `!` 提示后面的语句不可达。

## 表达不会发生的错误

标准库的 `FromStr` 用一个关联类型表示可能发生的错误。下面是省略文档和属性的接口：

```rust
pub trait FromStr: Sized {
    type Err;
    fn from_str(s: &str) -> Result<Self, Self::Err>;
}
```

如果解析只需要把原始字符串保存下来，不存在解析失败的输入，那么 `Err` 就能设为 `!`。

```rust
use std::str::FromStr;

#[derive(PartialEq, Debug)]
struct Text(String);

impl FromStr for Text {
    type Err = !;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        Ok(Self(s.to_owned()))
    }
}

fn main() {
    let Ok(text) = "hello".parse::<Text>();
    assert_eq!(text, Text(String::from("hello")));
}
```

当错误类型为 `!` 时，不可能构造 `Err`，所以上例的 `let Ok(text)` 不会匹配失败。如果需要兼容更早的编译器，可用 [`std::convert::Infallible`](https://doc.rust-lang.org/std/convert/enum.Infallible.html) 表达无错误类型；必要时显式处理 `Err(e) => match e {}`。

从值的个数来看，`Result<Text, !>` 没有比 `Text` 多出一种可构造的情况。在 Rust 1.100.0 上也可比较 `std::mem::size_of::<Result<Text, !>>()` 与 `std::mem::size_of::<Text>()` 的结果；实测大小相同不意味着两者拥有相同的 ABI。

## Edition 2024 的类型推断

分支里的 `!` 有明确的目标类型时仍会正常强制转换。如果没有足够约束，Edition 2024 的 [never type fallback](https://doc.rust-lang.org/edition-guide/rust-2024/never-type-fallback.html) 从 `()` 改为 `!`。如果旧代码实际依赖推断出 `()`，请显式写出类型，例如把 `f()?;` 改成 `let (): () = f()?;`。
