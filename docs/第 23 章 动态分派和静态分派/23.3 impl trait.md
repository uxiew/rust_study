# 23.3 impl trait

`impl Trait` 可以用来返回具体但不透明的类型。比如：

---

```rust
fn foo(n: u32) -> impl Iterator<Item=u32> {
    (0..n).map(|x| x * 100)
}
```

---

下面我们来讲解`impl Iterator<Item=u32>`。

我们注意到，在写泛型函数的时候，参数传递方式可以有：静态分派或动态分派两种选择：

---

```rust
fn consume_iter_static<I: Iterator<Item = u8>>(iter: I) -> u8 {
    iter.sum()
}

fn consume_iter_dynamic(iter: Box<dyn Iterator<Item = u8>>) -> u8 {
    iter.sum()
}
```

---

不论选用哪种方式，都可以写出针对一组类型的抽象代码，而不是针对某一个具体类型的。在`consume_iter_static`版本中，编译器按实际用到的类型实例化不同版本的函数。在`consume_iter_dynamic`版本中，每次调用的时候，实参的具体类型隐藏在了 trait object 的后面，通过虚函数表，在执行阶段选择调用正确的函数版本。

这两种方式都可以在函数参数中正常使用。但是，如果我们考虑函数的返回值，早期 Rust 没有稳定的 `impl Trait` 时，可以用装箱的 trait object 作为返回值：

---

```rust
fn produce_iter_dynamic() -> Box<dyn Iterator<Item = u8>> {
    Box::new(0..10)
}
```

---

以下这种方式是不合法的：

---

预期 E0782：`Iterator` 是 trait，不是可直接返回的类型。

```rust,compile_fail,no_run
fn produce_iter_static() -> Iterator<Item = u8> {
    0..10
}
```

---

不能直接把 trait 名当作返回类型。还没有不装箱的抽象返回类型时，常遇到以下问题：

* 我们返回一个复杂的迭代器的时候，会让返回类型过于复杂，而且泄漏了具体实现。比如，如果我们需要返回一个栈上的迭代器，可能需要为函数写复杂的返回类型：

---

```text
// 旧版迭代器签名示意（名称并非当前标准库 API）
Chain<Map<'a, (int, u8), u16, Enumerate<Filter<'a, u8, vec::MoveItems<u8>>>>, SkipWhile<'a, u16, Map<'a, &u16, u16, slice::Items<u16>>>>
```

---

函数内部的逻辑稍微有点变化，这个返回类型就要跟着改变，远不如泛型函数参数`T: Iterator`的抽象程度好。

* 函数无法直接返回一个闭包。因为闭包的类型是编译器自动生成的一个匿名类型，我们没办法在函数的返回类型中手工指定，所以在返回位 `impl Trait` 稳定之前，若要返回捕获环境的闭包，通常会把它装箱为 trait object。

---

```rust
fn multiply(m: i32) -> Box<dyn Fn(i32)->i32> {
    Box::new(move |x|x*m)
}

fn main() {
    let f = multiply(5);
    println!("{}", f(2));
}
```

---

请注意，这种时候引入一个泛型参数代表这个闭包是行不通的：

---

预期 E0308：函数体选择的具体闭包类型不等于调用方指定的 `T`。

```rust,compile_fail,no_run
fn multiply<T>(m: i32) -> T where T:Fn(i32)->i32 {
    move |x|x*m
}

fn main() {
    let f = multiply::<fn(i32) -> i32>(5);
    println!("{}", f(2));
}
```

---

编译出错，编译错误为：

---

```text
error[E0308]: mismatched types
expected type parameter `T`, found closure
```

---

因为泛型这种语法实际的意思是，泛型参数 T 由“调用者”决定。比如`std::iter::Iterator::collect`这个函数就非常适合这样实现：

---

```rust
let a = [1, 2, 3];
let doubled = a.iter().map(|&x| x * 2).collect::<Vec<_>>();
let queued = a.iter().map(|&x| x * 2).collect::<std::collections::VecDeque<_>>();
assert_eq!(doubled[0], queued[0]);
```

---

使用者可以在 `collect::<...>()` 中指定不同的类型，如`Vec<i32>`、`VecDeque<i32>`、`LinkedList<i32>`等。这个 collect 方法的返回类型是一个抽象的类型集合，调用者可以随意选择这个集合中的任意一个具体类型。

这跟我们上面想返回一个内部的闭包情况不同，上面的程序想表达的是返回一个“具体类型”，这个类型是由被调用的函数自行决定的，只是调用者不知道它的名字而已。

为了解决上面的问题，aturon 提出了 [impl trait 这个方案](https://github.com/rust-lang/rfcs/pull/1951)。此方案引入了一个新的语法，可以表达一个不用装箱的匿名类型，以及它所满足的基本接口。

示例如下：

---

```rust
fn multiply(m: i32) -> impl Fn(i32)->i32 {
    move |x|x*m
}

fn main() {
    let f = multiply(5);
    println!("{}", f(2));
}
```

---

这里的`impl Fn(i32)-> i32`表示，这个返回类型，虽然我们不知道它的具体名字，但是知道它满足`Fn(i32) -> i32`这个 trait 的约束。因此，它解决了“返回不装箱的抽象类型”问题。

它跟泛型函数的主要区别是：泛型函数的类型参数是函数的调用者指定的；返回位 `impl Trait` 的具体类型是函数的实现体指定的。

## 适用位置与稳定状态

旧版示例使用 `conservative_impl_trait` 实验开关。如今函数参数位与返回位都已稳定，且不需要这个开关。

| 位置 | 示例 | 稳定状态 |
| --- | --- | --- |
| 函数参数 | `fn print(x: impl Display)` | 稳定；近似匿名泛型参数 |
| 函数返回值 | `fn range() -> impl Iterator<Item = u8>` | 稳定；隐藏具体返回类型 |
| trait 方法返回值 | `fn items(&self) -> impl Iterator<Item = u8>` | 自 1.75 稳定 |
| 类型别名右侧 | `type Items = impl Iterator<Item = u8>` | Nightly：`type_alias_impl_trait` |
| impl 中的关联类型右侧 | `type Items = impl Iterator<Item = u8>` | Nightly：`impl_trait_in_assoc_type` |

```rust
use std::fmt::Display;

fn format_value(value: impl Display) -> String {
    value.to_string()
}

fn even_numbers() -> impl Iterator<Item = u8> + Clone {
    (0..6_u8).filter(|n| n % 2 == 0)
}

fn main() {
    assert_eq!(format_value(7), "7");
    assert_eq!(even_numbers().clone().collect::<Vec<_>>(), [0, 2, 4]);
}
```

两个独立的参数位 `impl Trait` 可以是不同类型；如果要让二者共享同一个类型参数，请用 `fn f<T: Trait>(a: T, b: T)`。返回位若希望调用者使用 `Clone` 等额外接口，应在签名中声明对应约束。

同一函数的返回分支必须产生同一种具体类型。下面预期 E0308：`Range<u8>` 与 `Once<u8>` 即使都实现 `Iterator`，也不是同一类型。若确实需要返回不同类型，可以用枚举包装，或改用 `Box<dyn Iterator<Item = u8>>`。

```rust,compile_fail,no_run
fn values(many: bool) -> impl Iterator<Item = u8> {
    if many { 0..3 } else { std::iter::once(0) }
}
```

::: tip 新版变化
自 Rust 1.75 起，trait 可以在返回位置使用 `impl Trait`，也可以声明 `async fn`。二者都不会让相应的方法自动支持动态分派。Edition 2024 中，普通函数的返回位 `impl Trait` 默认可捕获作用域内的所有泛型参数（包括生命周期）；需要精确指定时可使用 `use<...>`。
:::

```rust
trait Bytes {
    fn bytes(&self) -> impl Iterator<Item = u8> + '_;
}

impl Bytes for String {
    fn bytes(&self) -> impl Iterator<Item = u8> + '_ {
        self.as_str().bytes()
    }
}

fn main() {
    let text = String::from("ab");
    assert_eq!(Bytes::bytes(&text).collect::<Vec<_>>(), [b'a', b'b']);
}
```

如果必须给不透明类型起别名，以下两个位置在稳定版还不可用。这个实验示例需要 Nightly 的 `type_alias_impl_trait` 和 `impl_trait_in_assoc_type`；`#[define_opaque]` 指明由哪个函数确定别名背后的具体类型。

```rust:{channel:"nightly",edition:"2024"}
#![feature(type_alias_impl_trait, impl_trait_in_assoc_type)]

type Values = impl Iterator<Item = u8>;

#[define_opaque(Values)]
fn values() -> Values {
    0..3
}

trait Source {
    type Items: Iterator<Item = u8>;
    fn items(&self) -> Self::Items;
}

impl Source for () {
    type Items = impl Iterator<Item = u8>;
    fn items(&self) -> Self::Items {
        3..5
    }
}

fn main() {
    assert_eq!(values().chain(().items()).collect::<Vec<_>>(), [0, 1, 2, 3, 4]);
}
```

## 不透明接口的取舍

不必用 `impl Trait` 替换每个具体类型。比如在迭代器的例子中，写具体的 `Chain<Map<...>, ...>` 会暴露实现，但调用方也可以使用具体类型公开的其他接口。`impl Iterator<Item = u16>` 更精简，却不承诺 `Clone`。若允许调用方克隆迭代器，可以将约束写成 `impl Iterator<Item = u16> + Clone`，如上面的 `even_numbers`。如果需要 `ExactSizeIterator` 等其他保证，也要显式列出相应约束，而且实际返回类型必须满足它们。

有时调用方确实需要保留完整的具体类型，此时直接公开具名类型，比罗列一长串 trait 更清晰。用于编译器内部的 `TrustedLen` 仍不在稳定接口中，不应列为稳定库的公开约束。

参见 [trait 中的 impl Trait 与 async fn](https://blog.rust-lang.org/2023/12/21/async-fn-rpit-in-traits/)和 [Edition 2024 的返回位生命周期捕获](https://doc.rust-lang.org/edition-guide/rust-2024/rpit-lifetime-capture.html)。
