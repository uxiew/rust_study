# 18.4 小结

Rust 语言是跟 C++非常相似的一门语言。它们的定位相似，目标一致，都没有 GC，都面向底层硬件，都希望提供比较好的高级抽象能力，都对性能有非常高的要求。而这也意味着，在许多情况下，它们会碰到同样的问题，有着类似的设计思路。

Rust 和 C++ 都要面对在执行一半时中断的问题：清理资源和保持内部不变量是共同的挑战。Rust 用借用、RAII 与 `UnwindSafe` 等工具帮助隔离风险，但即使代码不含 `unsafe`，也仍要设计好业务状态的一致性。

例如，转账先扣除一方余额、后增加另一方余额。如果在两步之间 panic，展开可以释放锁，却不会替业务回滚扣款。这里的“异常安全”关注的是中断后哪些不变量还成立；它和是否泄漏资源、是否发生未定义行为，是不同的问题。

在“系统级”编程语言这个“紧箍咒”之下，许多看似简单的设计都需权衡易用性、安全性和性能。引入 Edition 也并不意味着放弃兼容性。

最后要强调的是，panic 并不意味着“内存不安全”，恰恰相反，它是阻止“内存不安全”的利器。内存不安全造成的问题比程序突然退出要严重得多。在即将发生内存不安全现象的时候，如果当时已经没有任何其他选择，panic 至少可以避免最坏情况的发生。然后我们可以很快发现事故的第一现场，从而修复代码，使其继续执行。
