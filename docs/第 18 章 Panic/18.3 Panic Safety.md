# 18.3 Panic Safety

Panic 可能从 `Clone`、比较函数或回调中抛出。对安全代码，最低要求是保持对象的类型不变量；对 `unsafe` 代码，还必须保证展开过程不会误读、重复析构或释放无效内存。

## 先完成可能失败的操作，再提交状态

下面先构造新内容，成功后才替换目标。即使某一次 `clone` panic，临时 `Vec` 也只会析构已经添加成功的元素，目标不变。

```rust
fn replace_all<T: Clone>(target: &mut Vec<T>, source: &[T]) {
    let replacement: Vec<T> = source.to_vec();
    *target = replacement;
}

let mut target = vec![1];
replace_all(&mut target, &[2, 3]);
assert_eq!(target, [2, 3]);
```

这个顺序防的是构造新内容时的 panic，不代表析构旧内容等后续操作永远不会 panic。

## 捕获 panic 后还能用数据吗？

预期编译错误：（E0277）闭包捕获了 `&mut Vec<_>`，不满足 `UnwindSafe`。捕获后，调用方可能看到更新到一半的数据。

```rust,compile_fail,no_run
use std::panic::catch_unwind;

fn main() {
    let mut values = vec![1];
    let _ = catch_unwind(|| {
        values.push(2);
        panic!("更新中途失败");
    });
}
```

| 工具 | 含义 |
| --- | --- |
| `UnwindSafe` | 提醒调用方检查展开后可观察的状态，不是内存安全证明。 |
| `AssertUnwindSafe` | 显式接受该状态；不会回滚，也不修复不变量。 |
| `Mutex` 中毒 | 可能提示持锁线程 panic；是提示，不是可靠的安全屏障。 |

面对部分初始化的容器，需要在每一步成功后记录已初始化的元素数。第 20.7 节给出 `Vec` 的最小示例。
