# 29.2 Mutex

`Mutex<T>` 允许多个线程共享数据，但每次只让一个线程获得锁。调用 `lock()` 会等待锁，`try_lock()` 则在无法立即获得锁时返回错误。拿到 `MutexGuard` 后，可以读写数据；守卫析构时自动解锁。

```rust
use std::{sync::Mutex, thread};

fn main() {
    let balance = Mutex::new(0);
    thread::scope(|scope| {
        for change in [5, -5] {
            let balance = &balance;
            scope.spawn(move || {
                *balance.lock().unwrap() += change;
            });
        }
    });

    assert_eq!(*balance.lock().unwrap(), 0);
}
```

这里的作用域线程借用同一把锁；若用普通的 `spawn`，则通常用 `Arc<Mutex<T>>` 给每个线程一份共享所有权。`T: Send` 时 `Mutex<T>` 同时实现 `Send` 和 `Sync`，不要求受保护的值本身是 `Sync`。

```mermaid
flowchart LR
    A["线程调用 lock"] --> B["取得锁并获得守卫"]
    B --> C["通过守卫读写数据"]
    C --> D["守卫析构，释放锁"]
```

`lock()` 返回 `LockResult<MutexGuard<'_, T>>`。如果某个线程在持锁时 panic，锁通常会被标记为**中毒**（poisoned），后续加锁时会收到 `PoisonError`，以提示内部数据可能不再满足业务约束。错误中仍含有已获得锁的守卫；确定可以恢复时，可用 `into_inner()` 取得守卫，修正数据后再用 `clear_poison()` 清除标记。中毒只是提示，不能作为 `unsafe` 代码的安全保证。
