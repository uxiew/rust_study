# 29.10 总结

| 需求 | 优先考虑 |
| --- | --- |
| 跨线程共享所有权 | `Arc<T>`；它只同步引用计数 |
| 共享并修改多字段数据 | `Mutex<T>`；如果通常只读，也可考虑 `RwLock<T>` |
| 独立计数器 | 原子整数；用 `fetch_add` 等读改写操作完成更新 |
| 多个线程在同一点会合 | `Barrier` |
| 等待共享状态达到条件 | `Mutex<T>` 与 `Condvar` |
| 每个线程有自己的状态 | `thread_local!` |

`RefCell<T>` 不是 `Sync`，但在 `T: Send` 时可以整个移交给另一个线程。类似地，`Arc<T>` 不会让内部的 `T` 自动变成线程安全的。

安全 Rust 防止数据竞争，并不防止死锁或丢失更新等逻辑错误。每种同步机制也都有开销；如果只是把数据交给另一个线程处理，可以考虑下一章的消息管道。
