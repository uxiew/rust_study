
# 29.4 Atomic

标准库的原子类型在 `std::sync::atomic` 模块里。例如 `AtomicIsize` 提供了能跨线程共享的整数操作。对普通整数加 1，其过程是读取、计算、写回；原子类型则提供 `fetch_add` 把这三步合成一次原子读改写。标准库会使用目标平台支持的原子操作，具体指令不一定相同。

接着看两个线程对共享整数做加减的例子：

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicIsize, Ordering};
use std::thread;

const COUNT: u32 = 1_000_000;
fn main() {
    // Atomic 系列类型同样提供了线程安全版本的内部可变性
    let global = Arc::new(AtomicIsize::new(0));

    let clone1 = global.clone();
    let thread1 = thread::spawn(move || {
        for _ in 0..COUNT {
            clone1.fetch_add(1, Ordering::SeqCst);
        }
    });

    let clone2 = global.clone();
    let thread2 = thread::spawn(move || {
        for _ in 0..COUNT {
            clone2.fetch_sub(1, Ordering::SeqCst);
        }
    });

    thread1.join().unwrap();
    thread2.join().unwrap();
    assert_eq!(global.load(Ordering::SeqCst), 0);
}
```

一个线程每次加 1，另一个每次减 1，不管两边怎样交错，读改写操作都不会覆盖对方的更新，所以最后回到 0。若改成先 `load`，单独计算，再 `store` 呢？

## 29.4.1 分开的原子读写仍可能丢失更新

下面将这个对照改成每个线程只加一次，用屏障固定交错顺序，避免靠运气复现：

```rust
use std::{
    sync::{Barrier, atomic::{AtomicUsize, Ordering}},
    thread,
};

fn main() {
    let counter = AtomicUsize::new(0);
    let both_loaded = Barrier::new(2);

    thread::scope(|scope| {
        for _ in 0..2 {
            scope.spawn(|| {
                let old = counter.load(Ordering::SeqCst);
                both_loaded.wait();
                counter.store(old + 1, Ordering::SeqCst);
            });
        }
    });
    assert_eq!(counter.load(Ordering::SeqCst), 1);

    counter.store(0, Ordering::Relaxed);
    thread::scope(|scope| {
        for _ in 0..2 {
            scope.spawn(|| {
                counter.fetch_add(1, Ordering::Relaxed);
            });
        }
    });
    assert_eq!(counter.load(Ordering::Relaxed), 2);
}
```

屏障让两个线程都先读到 0，再分别写 1，所以第一次的结果确定是 1。第二次，每次 `fetch_add` 都作用在最新的计数上，不会覆盖另一线程的更新。

| 内存序 | 适用场景 |
| --- | --- |
| `Relaxed` | 操作本身仍是原子的，但不负责为其他内存访问建立同步；例如这里的独立计数器 |
| `Release` / `Acquire` | 发布和观察数据：当 acquire 读取到相应 release 发布的值时，建立同步 |
| `SeqCst` | 还为采用该内存序的操作提供一致的全局顺序，但不会合并多次原子操作 |

可以借用上节的锁来做类比：前一种写法就像一次持锁覆盖了“读、算、写”；后一种则像读完就放锁，到了写回才重新拿锁。这里只是类比操作边界，原子操作本身并不等于加了互斥锁。后一种写法没有数据竞争，却有丢失更新的逻辑错误。需要同时更新多项共享数据时，通常用一把锁保护整个操作，比组合多个原子操作更直接。
