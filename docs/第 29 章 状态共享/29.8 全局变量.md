# 29.8 全局变量

读写 `static mut` 需要 `unsafe`。下面是完整反例：

```rust,compile_fail,no_run
static mut COUNT: i32 = 0;

fn main() {
    COUNT = 1;
}
```

预期报错 **E0133**：修改可变静态项需要 `unsafe`。

```text
error[E0133]: use of mutable static is unsafe and requires unsafe function or block
```

加上 `unsafe` 并不会自动处理同步或别名约束。

::: tip 新版变化
Edition 2024 默认拒绝创建指向 `static mut` 的引用（包括某些隐式借用）。优先使用原子类型、`Mutex<T>` 或 `LazyLock<T>`，将同步约束放进类型里。
:::

不用 `mut` 的全局变量也可能具有内部可变性。例如，`Cell::set` 可以通过共享引用修改值，所以只看静态项的声明是否带 `mut` 并不够。试着声明一个这样的共享 `static`：

```rust,compile_fail,no_run
use std::cell::Cell;

static COUNT: Cell<i32> = Cell::new(0);

fn main() {
    COUNT.set(1);
}
```

预期报错 **E0277**：`Cell<i32>` 有内部可变性，却没有跨线程同步，所以不是 `Sync`。即使不创建线程，编译器也会在静态项声明处报错。

```text
error[E0277]: `Cell<i32>` cannot be shared between threads safely
```

为什么不能只靠 `spawn` 的约束？线程访问全局变量时，闭包可能没有捕获任何局部数据，本身仍满足 `Send`，但不同线程会访问同一份全局状态。因此共享 `static` 的类型必须实现 `Sync`。对于全局计数器，可改用原子整数：

```rust
use std::{sync::atomic::{AtomicUsize, Ordering}, thread};

static COUNT: AtomicUsize = AtomicUsize::new(0);

fn main() {
    let worker = thread::spawn(|| COUNT.fetch_add(1, Ordering::Relaxed));
    COUNT.fetch_add(1, Ordering::Relaxed);
    worker.join().unwrap();
    assert_eq!(COUNT.load(Ordering::Relaxed), 2);
}
```

| 全局状态 | 推荐类型 |
| --- | --- |
| 独立计数或标记 | 原子整数或 `AtomicBool` |
| 多字段共享可变状态 | `Mutex<T>` 或 `RwLock<T>` |
| 首次访问时初始化 | `LazyLock<T>`；若由调用者提供初始值，可用 `OnceLock<T>` |
