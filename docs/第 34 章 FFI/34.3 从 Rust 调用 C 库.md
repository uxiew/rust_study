# 34.3 从 Rust 调用 C 库

这次反过来，让 Rust 调用 C 的函数。保存为 `simple_math.c`。C 端自行检查输入范围，超出范围返回 `-1`，这样任何 `int` 实参都不会导致有符号整数溢出。

```c
int add_square(int a, int b) {
    if (a < -100 || a > 100 || b < -100 || b > 100) {
        return -1;
    }
    return a * a + b * b;
}
```

把 C 函数编译为静态库：

```bash
cc -Wall -Wextra -c simple_math.c -o simple_math.o
ar rcs libsimple_math.a simple_math.o
```

保存为 `call_math.rs`。Edition 2024 要求 `extern` 块带 `unsafe`：声明者负责让签名和 ABI 与实际的 C 定义一致。`extern` 块里的函数默认是 `unsafe fn`；这里的函数没有额外调用前提，因此可声明为 `safe fn`。

```rust,no_run
use std::ffi::c_int;

#[link(name = "simple_math", kind = "static")]
// SAFETY: 签名与 simple_math.c 一致，且 C 端对所有 int 输入都有定义。
unsafe extern "C" {
    safe fn add_square(a: c_int, b: c_int) -> c_int;
}

fn main() {
    assert_eq!(add_square(2, 2), 8);
    assert_eq!(add_square(0, 0), 0);
    assert_eq!(add_square(101, 2), -1);
    println!("{}", add_square(2, 2));
}
```

如果外部函数要求调用方提供有效指针、初始化状态或特定数值范围，应声明为 `unsafe fn`，并写清楚调用前提；不要为了省略调用处的 `unsafe` 就标成 `safe`。

示例要链接刚构建的静态库：`#[link]` 指定库名和类型，`-L native=.` 指定本地库的查找目录。

```bash
rustc --edition=2024 -L native=. call_math.rs
./call_math
```

预期输出为 `8`。
