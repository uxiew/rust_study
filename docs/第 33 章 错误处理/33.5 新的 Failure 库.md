# 33.5 新的 Failure 库

::: tip 新版变化
`failure` 是旧版 Rust 生态中的错误处理库，现已[停止维护](https://rustsec.org/advisories/RUSTSEC-2020-0036.html)，不建议在新项目采用。新代码优先围绕标准库的 `std::error::Error`；按需选用 `thiserror` 或 `anyhow`。
:::

| 需要什么 | 常用选择 |
| --- | --- |
| 库要公开可匹配的错误类型 | 用枚举表示错误；用 `thiserror` 派生 `Display`、`Error` 等实现 |
| 应用要把不同错误一路上报，并附上操作上下文 | 用 `anyhow::Result<T>`，通过 `Context` 补充“哪一步失败” |
| 不想引入依赖 | 手写 `Display`、`Error`；也可用 `Box<dyn Error + Send + Sync>` 统一传递可跨线程的错误 |

`Error::source()` 可以串起底层原因；展示错误文本请用 `Display`，不要再实现已弃用的 `description()` 或 `cause()`。

下面用 `thiserror` 简化前面示例中的自定义枚举。需要在 Cargo 项目中先运行 `cargo add thiserror@2`，再把代码保存为 `src/main.rs`。

```rust,ignore,no_run
use std::{fs, io, path::Path};

#[derive(Debug, thiserror::Error)]
enum ReadNumberError {
    #[error("读取文件失败")]
    Io(#[from] io::Error),
    #[error("文件内容不是 i32 整数")]
    Parse(#[from] std::num::ParseIntError),
}

fn read_number(path: impl AsRef<Path>) -> Result<i32, ReadNumberError> {
    let text = fs::read_to_string(path)?;
    Ok(text.trim().parse()?)
}

fn main() -> Result<(), ReadNumberError> {
    println!("{}", read_number("number.txt")?);
    Ok(())
}
```

`#[from]` 生成 `?` 所需的 `From` 实现，也把原错误保留为 `source()`。这样调用方既能对 `ReadNumberError` 做模式匹配，也能看到底层 I/O 或解析错误。
