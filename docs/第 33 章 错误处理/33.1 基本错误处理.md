# 33.1 基本错误处理

先判断你需要表达的是**缺少值**，还是**需要解释失败原因**。

| 类型 | 返回值 | 示例 |
| --- | --- | --- |
| `Option<T>` | `Some(T)` 或 `None` | 查找子串：找不到不是异常 |
| `Result<T, E>` | `Ok(T)` 或 `Err(E)` | 打开文件：可能不存在，也可能没权限 |

## 缺少值：`Option`

`str::find` 返回子串第一次出现的**字节偏移**；找不到时返回 `None`。下面的 C 接口则用空指针表达“未找到”，而 `Option` 让这两种情况直接出现在类型中。

```c
char *strstr(const char *str, const char *substr);
```

只有“找到”和“没找到”两种结果时，空指针就够用。但有时既要说明失败原因，又要返回成功时拿到的值，单靠一个特殊值就不方便了。

```rust
fn main() {
    assert_eq!("你好 Rust".find("Rust"), Some(7));
    assert_eq!("你好 Rust".find("Go"), None);
}
```

## 失败原因：`Result`

`std::fs::File::open` 的返回类型是 `std::io::Result<File>`。`std::io::Result<T>` 是下面这个类型的别名，并不是另一种枚举：

```rust
pub type Result<T> = std::result::Result<T, std::io::Error>;
```

这样可以根据错误的种类区分处理，而不用像某些 C 接口那样用返回值传回错误码、另用输出参数传回成功值。

比如，C 的 `fopen` 返回文件指针，失败返回空指针；要了解错误原因须另行查询。C11 的可选接口 `fopen_s` 则返回错误码，文件指针经参数传回：

```c
FILE *fopen(const char *restrict filename, const char *restrict mode);

errno_t fopen_s(FILE *restrict *restrict streamptr,
                const char *restrict filename,
                const char *restrict mode);
```

相比之下，`Result` 把两种情况放进同一个返回类型里，调用方用一次模式匹配就能区分它们。

```rust
use std::fs::File;
use std::io::ErrorKind;

fn main() {
    match File::open("settings.toml") {
        Ok(_) => println!("已打开配置"),
        Err(err) if err.kind() == ErrorKind::NotFound => println!("使用默认配置"),
        Err(err) => eprintln!("无法打开配置：{err}"),
    }
}
```

## 解析时的错误类型

`str::parse::<T>()` 调用类型 `T` 的 [`FromStr`](https://doc.rust-lang.org/std/str/trait.FromStr.html) 实现。`FromStr::Err` 由目标类型决定：解析 `bool` 可能得到 `ParseBoolError`，解析 `f32` 则可能得到 `ParseFloatError`。

标准库的 trait 声明如下。泛型调用方不必假定具体的错误类型，只需使用实现选择的 `Self::Err`：

```rust
pub trait FromStr: Sized {
    type Err;
    fn from_str(s: &str) -> Result<Self, Self::Err>;
}
```

`bool` 只接受 `"true"` 和 `"false"`；`ParseBoolError` 不需要记录失败的其他细节。下面摘录[标准库的实现](https://doc.rust-lang.org/1.100.0/src/core/str/traits.rs.html#899-932)，省略文档和属性。它使用库内部构造错误的方式，不是可以在应用里重写的 impl：

```text
impl FromStr for bool {
    type Err = ParseBoolError;

    fn from_str(s: &str) -> Result<bool, ParseBoolError> {
        match s {
            "true" => Ok(true),
            "false" => Ok(false),
            _ => Err(ParseBoolError),
        }
    }
}
```

而浮点数解析器内部要区分空字符串与无效输入。下面是 `ParseFloatError` 内部使用的[错误种类](https://doc.rust-lang.org/1.100.0/src/core/num/float_parse.rs.html#115-119)：

```text
pub(super) enum FloatErrorKind {
    Empty,
    Invalid,
}
```

```rust
fn main() {
    assert_eq!("true".parse::<bool>().unwrap(), true);
    assert!("".parse::<f32>().is_err());
    assert!("yes".parse::<bool>().is_err());
}
```

把 `&str` 转成 `String` 不存在解析失败。Rust 1.100 中，关联错误类型 `std::string::ParseError` 是永不类型 `!` 的别名。它没有任何值，因此不存在可构造的 `Err`。下面可以观察当前工具链上的大小；不要把这一结果推广为所有 `Result` 的布局保证。

```rust
use std::mem::{size_of, size_of_val};
use std::string::ParseError;

fn main() {
    let parsed: Result<String, ParseError> = "hello".parse();
    println!("String：{} 字节", size_of::<String>());
    println!("Result：{} 字节", size_of_val(&parsed));
}
```
