# 33.2 组合错误类型

用 `Result` 的组合方法，可以串起多步操作，不必每一步都写 `match`。

从方法签名读起（这里省略了 `impl<T, E> Result<T, E>` 及实现体）：

```text
fn map<U, F>(self, op: F) -> Result<U, E> where F: FnOnce(T) -> U;
fn map_err<F, O>(self, op: O) -> Result<T, F> where O: FnOnce(E) -> F;
fn and<U>(self, res: Result<U, E>) -> Result<U, E>;
fn and_then<U, F>(self, op: F) -> Result<U, E> where F: FnOnce(T) -> Result<U, E>;
fn or<F>(self, res: Result<T, F>) -> Result<T, F>;
fn or_else<F, O>(self, op: O) -> Result<T, F> where O: FnOnce(E) -> Result<T, F>;
```

表中只留下参数类型和运行条件，便于比较：

| 方法 | 何时使用参数 | 参数 |
| --- | --- | --- |
| `map` | 成功时转换值 | `T -> U` |
| `map_err` | 出错时转换错误 | `E -> F` |
| `and` | 成功时返回另一个结果 | `Result<U, E>` |
| `and_then` | 成功时执行下一步可失败的操作 | `T -> Result<U, E>` |
| `or` | 出错时返回另一个结果 | `Result<T, F>` |
| `or_else` | 出错时执行补救操作 | `E -> Result<T, F>` |

`and`、`or` 的参数会先求值；希望按需执行时，用接收闭包的 `and_then`、`or_else`。

例如，如果有参数，先用 `and_then` 解析整数，因为解析可能失败；拿到整数以后，再用 `map` 把它翻倍。这里要先把解析错误变成与“缺少参数”相同的错误类型 `String`，所以用 `map_err`。类似的组合方法也见于 `Option`；比较时可先看闭包是否也返回一个 `Option`。

```rust
fn double_arg(arg: Option<&str>) -> Result<i64, String> {
    arg.ok_or_else(|| "缺少参数".to_owned())
        .and_then(|text| text.parse::<i32>().map_err(|err| err.to_string()))
        .map(|n| 2 * i64::from(n))
}

fn main() {
    assert_eq!(double_arg(Some("21")), Ok(42));
    assert_eq!(double_arg(None), Err("缺少参数".to_owned()));
    assert!(double_arg(Some("")).is_err());
    assert!(double_arg(Some("Rust")).is_err());
}
```
