# 14.3 小结

判断一次访问是否冲突，先找被借用的位置和借用方式，再沿控制流查看引用之后是否还会被使用。NLL 不改变变量作用域或析构次序，也不负责打破引用计数环或保证没有死锁。

原书用交通规则打比方：需要绕路并不否定规则本身，改进应当让实际上不冲突的路线少绕路。词法检查器把借用保守地算到代码块末尾，NLL 则根据后续访问缩短借用；两者防止的仍是同样的读写冲突。C/C++ 的指针使用规范和静态分析也能帮助找出问题，不过 Rust 把所有权和借用写进了类型及函数签名，让调用处无需阅读实现就能检查一部分约束。

如果检查器不能证明两次访问不冲突，优先让访问顺序更明确，或选择能直接表达操作的 API。例如，要给 `HashMap` 中的缺失键插入默认值，再修改它，使用 `entry`，不用先 `get_mut` 再单独 `insert`：

```rust
fn main() {
    use std::collections::HashMap;

    let mut counts = HashMap::new();
    *counts.entry("rust").or_insert(0) += 1;
    assert_eq!(counts["rust"], 1);
}
```
