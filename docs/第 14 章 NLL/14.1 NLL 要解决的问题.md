# 14.1 NLL 希望解决的问题

首先，看个简单的示例：

```rust
fn foo() -> Vec<char> {
    let mut data = vec!['a', 'b', 'c']; // --+ 'scope
    capitalize(&mut data[..]);          //   |
//  ^~~~~~~~~~~~~~~~~~~~~~~~~ 'lifetime //   |
    data.push('d');                     //   |
    data.push('e');                     //   |
    data.push('f');                     //   |
    data                                //   |
//  <-----------------------------------------+
}

fn capitalize(data: &mut [char]) {
    for c in data {
        c.make_ascii_uppercase();
    }
}

fn main() {
    let v = foo();
    println!("{:?}", v);
}
```

这段代码是没有问题的。我们的关注点是`foo()`这个函数，它在调用`capitalize`函数的时候，创建了一个临时的`&mut`型引用，在它的调用结束后，这个临时的借用就终止了，因此，后面我们就可以再用`data`去修改数据。注意，这个临时的`&mut`引用存在的时间很短，函数调用结束，它的生命周期就结束了。

把临时借用改成具名的 `slice`，就能看到早期和现代检查器的差别。这段代码在今天的 Rust 中也能通过：

```rust
fn foo() -> Vec<char> {
    let mut data = vec!['a', 'b', 'c'];
    let slice = &mut data[..];
    capitalize(slice); // 借用没有后续用途
    data.push('d');
    data.push('e');
    data.push('f');
    data
}
fn capitalize(data: &mut [char]) { for c in data { c.make_ascii_uppercase(); } }

fn main() { assert_eq!(foo(), ['A', 'B', 'C', 'd', 'e', 'f']); }
```

早期的词法检查器可能把具名 `slice` 的借用保守地延长到块末尾，因而拒绝后续 `push`。当时可以添加子作用域来明确借用边界：

```rust
fn foo() -> Vec<char> {
    let mut data = vec!['a', 'b', 'c']; // --+ 'scope
    {
        let slice = &mut data[..];      // <---- 创建一个代码块，让`slice`在这个子代码块中创建，就不会产生生命周期冲突问题了。
        capitalize(slice);              //   |
    }// <------------------------------------+
    data.push('d');
    data.push('e');
    data.push('f');
    data
}
fn capitalize(data: &mut [char]) { for c in data { c.make_ascii_uppercase(); } }
```

现在不需要这层额外作用域。NLL 不只是寻找源码上最后一行，它还能区分同一语句中的不同执行分支。

切片例子里冲突并不是“`slice` 这个名字还在”，而是旧检查器仍把从 `data` 借出的内存视为独占。由于 `push` 也需要 `&mut self`，两次访问不能重叠；`push` 还可能重新分配存储，导致仍被使用的切片失效。现代检查器发现这里不会再使用切片，因而能够放行。这和提前销毁 `data` 或对其调用 `drop` 是两回事。

```rust
use std::{collections::HashMap, hash::Hash};

fn process_or_default<K: Eq + Hash, V: Default>(
    map: &mut HashMap<K, V>,
    key: K,
    process: impl FnOnce(&mut V),
) {
    match map.get_mut(&key) {
        Some(value) => process(value),
        None => { map.insert(key, V::default()); }
    }
}
```

旧检查器可能把 `get_mut` 的借用延长到整个 `match`。顺着分支来看，只有 `Some` 会用到 `value`，在 `None` 分支则没有返回引用可继续使用。参见 [NLL RFC](https://github.com/rust-lang/rfcs/blob/master/text/2094-nll.md)。

如果要取出或插入默认值，`entry` 不必因插入再查找一遍，并可直接返回可变引用：

```rust
use std::{collections::HashMap, hash::Hash};

fn get_default3<K: Eq + Hash, V: Default>(map: &mut HashMap<K, V>, key: K) -> &mut V {
    map.entry(key).or_default()
}
```

这两种设计各有用途：`entry` 直接表达填入默认值；`match` 可以为已存在和不存在的情况各自执行不同操作。下面是一个完整的分支示例：

```rust
use std::collections::HashMap;

fn process_or_default4(map: &mut HashMap<String, String>, key: String)
{
    match map.get_mut(&key) {
        Some(value) => println!("{}", value),
        None => {
            map.insert(key, String::new());
        }
    }
}

fn main() {
    let mut map = HashMap::<String, String>::new();
    let key = String::from("abc");
    process_or_default4(&mut map, key);
}
```

## 小结

Rust 1.31 在 Edition 2018 中引入 NLL，1.63 起所有 Edition 使用同一套检查器。它可以放行不再活跃的借用，但仍会拒绝在修改后继续使用的借用。
